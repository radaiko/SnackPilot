The earlier blocker (typeText: "no element or descendant has keyboard focus")
was real: XCUIApplication.typeText cannot synthesize GPUI input. The fix keeps
production behaviour and changes only the evidence route:
- AppShell now drives the soft keyboard on iOS from focus changes
  (`WindowExt::has_focused_input` → `gpui_mobile::show_keyboard/hide_keyboard`);
  the kit Input's focus is the source of truth, no library patch.
- The password Input is `.masked(true)` (§3.5/§3.6 secure entry).
- `--detail=login|automaten` opens a credential screen on the first frame,
  same debug-knob pattern as `--tab`/`--dialog`.
- The UI test taps the *system keyboard keys* (accessible elements), which send
  real input through the focused field, and proves the field contents by pixel
  diffs of the field region.

Review round 1 follow-ups (fixed in this series):
- Abmelden now uses the §3.5 `buttonDanger` recipe (was white text on the page
  background). The authenticated state itself cannot be captured on iOS before
  task 5.7 installs the shell model, so the button's look is unverified by
  screenshot; the recipe is the same one the §4.1 destructive confirm uses.
- Both login fields pre-fill from the stored credentials on push
  (`AppModel::saved_credentials`, added for §3.5). The password pre-fill cannot
  be captured on iOS until 5.7 wires the model; the read is the platform keychain
  call the model already uses for auto-login.

Named gaps (not silently missing):
- Paste is not exercised by the UI test. XCUITest paste needs a long-press menu
  on a GPUI field, which this harness cannot drive; the kit Input's paste path is
  the shared gpui clipboard handler. Follow-up: drive paste on a physical device.
- On iOS before 5.7 (no session model installed) Speichern cannot persist or
  authenticate; it shows the §3.5 failure alert, as captured in f-save-alert.png.
  Save-before-login and the success alert are therefore verified by code and the
