Launch order implemented (`model/src/lifecycle.rs::bootstrap`):
1. cached menus/orders/billing months published first (core cache load, state
   only filled when the published state is still empty);
2. `app.launched` tracked;
3. broadcast fetched (best-effort; suppressed in test builds so no test reaches
   a host), 4. notification permission requested (debug `--no-permission-prompt`
   knob for capture runs), 5. company geofence restored idempotently (one
   `start_geofence` per install, persisted marker);
6. saved-credentials auto-login (Ventopay first with one billing fetch) and a
   log-state refresh.

Foreground: `on_foreground` refreshes orders + billing + broadcast under an
atomic re-entrancy guard; the broadcast banner is dismissible and `refresh`
clears the dismissed flag, so it returns on the next foreground.
Tests cover: `app.launched` tracked, geofence start once across two bootstraps,
dismissed banner returns after a foreground.

Gaps (recorded):
