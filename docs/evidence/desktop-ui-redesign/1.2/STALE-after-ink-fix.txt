============================================

The gallery captures in this directory predate the accent-ink and accent-edge
fixes of task 1.2. Three accent resolutions changed under REQ-UI-13, all derived
from the pinned tokens by `snackpilot_model::desktop`:

1. accent as text on the panel / rail: `desktop.accent_on_panel` /
   `desktop.accent_on_rail`, falling back to `text_primary` below 4.5:1;
2. accent as text on the selection fill: `desktop.accent_on_selection` (the
   selected chip's label and check);
3. accent as a boundary: `desktop.accent_boundary` (`boundary_ink`, 3:1 on the
   selection fill), now used by all three desktop edges — the selected card's
   1 px border (`card.rs:39`), the selected chip's 1 px border (`chip.rs:86`)
   and the record table's 3 px selected-row rule on `primary_surface`
   (`record_table.rs:83`). Light golden's accent misses 3:1 on that fill, so
   each of these now falls back to `text_primary` there.

A host reboot is required before recapturing. The Android emulator cannot boot
on this VM any more: every start, with the existing `headless` AVD or a freshly
created `fresh36` AVD, with KVM and with `-accel off`, stops inside the qemu
vCPU threads ("detected a hanging thread 'QEMU2 CPU0 thread'") and never brings
up adbd; three host processes are stuck uninterruptibly in
`kvm_async_pf_task_wait` and the emulator is offline (`emulator-5554 offline`),
which only a reboot clears. That reboot was not done from inside this session,
so it is left to the dispatcher. The app crate also cannot be built here
(missing `pkg-config`/fontconfig), and macOS screen captures were already
declared out of scope for this task run (`NOT-CAPTURED-macos.txt`).
