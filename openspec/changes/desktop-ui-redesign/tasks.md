# Tasks

domain: ui

Conventions for every task below (same contract fields as the archived gpui-kit rewrite):

- One task at a time, in order; no new worktree. All boxes remain unchecked until implementation, its evidence, `make check` and the loop's review gate pass, except an explicitly human-approved tick with deferred proof under the rule below. Two fix rounds, then stop for the human as `AGENTS.md` requires.
- Every acceptance item records `PASS`, `FAIL`, `BLOCKED(host|authorization)` or `DEFERRED-APPROVED`. A deferral names the criterion, approving human decision, owner/target task and outstanding evidence; it is never `PASS` and never consumes a coder fix round. A tick with deferred proof needs explicit human approval; mandatory trust/install evidence must pass before release readiness. Host deferral never waives required behaviour.
- `deps:` names **new dependencies/tools**, not preceding task IDs. Task ordering below defines prerequisites. `none` forbids manifest/lockfile changes; the existing pinned gpui set, Inter, Lucide and keyring features are reused. No edits to `src/core`, scraping specs/request shapes, CI or dependency manifests are authorised.
- `check:` is always `make check`; additional native/test commands are required, not replacements. `make check` contains `make ui-check` but does **not** execute app-crate tests or native UI/packaging tests. Run those explicitly when named. All new/changed tests have `// @req REQ-…` (or equivalent shell/PowerShell comment) referencing the requirement IDs below.
- `host:` Linux is this VM. Mac means `make mac-sync` then `ssh mac` with `export PATH=/opt/homebrew/bin:$HOME/.cargo/bin:$PATH` first in every remote command, working in `~/vm-sync/SnackPilot-gpui`. Windows means a human-provided **Windows 11 x64 native build/test host**, not assumed provisioned; if unavailable stop 1.7 and report. Do not allocate paid hosts or configure CI silently.
- **Mac desktop workflow:** in synced `src/ui`, `cargo build --locked -p snackpilot-app --bin snackpilot-desktop` and `cargo test --locked -p snackpilot-app --lib`; launch the real GUI binary with isolated offline fixture/demo data. A bounded 5-second no-panic run proves liveness only; real input and screenshots prove UI.
- **Mobile regression workflow:** after sync run `bash src/ui/ios/bootstrap.sh`, then from `src/ui/ios` `xcodebuild -project SnackPilot.xcodeproj -scheme SnackPilot -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build`, with current simulator ad-hoc settings. Install/launch a dedicated simulator and run XCUITests using a concrete UDID. Android: compile the Rust library with `bash tools/devops/ui-android-build.sh --release` as a check, then rebuild without `--release` (`bash tools/devops/ui-android-build.sh`) before `./gradlew :app:assembleDebug --no-daemon` in `src/ui/android` and captures; the debug APK must contain the debug library for gallery/debug evidence entries. Install/launch a working emulator/device. Do not delete a user's installed app/data for testing.
- **Evidence workflow:** fixture/demo only; disable/replace broadcast/network during evidence startup as well as service auth. No real hosts, credentials, cookies or live responses. Save images/command output/action traces in `docs/evidence/desktop-ui-redesign/<task-id>/`. Name every file in that task's handoff. Record content-area logical width and display scale; desktop roots/details at **360/720/1280**, plus **390/768** checkpoints, light/dark and representative interactions; all ten appearance/accent combinations checked. Mobile before/after comparisons retain current look even at wide widths, except for 1.2–1.5, whose mobile comparisons are `DEFERRED-APPROVED` under the approved rework deferral below. Missing native/capture evidence is a blocker, not a PASS inferred from compilation.
- File lists are edit allowlists including **new files**. The approved brief `docs/design/desktop-ui-redesign.md` is read-only except the human-approved narrow About/privacy copy amendments replacing TelemetryDeck with Aptabase under authoritative `docs/requirements/07-release.md`; these amendments are authorised here, not merely scope pointers in 1.8. Protected requirement edits are expressly called out below; normal spec sync/archive is a workflow follow-up, never an implementation file edit.
- **Native-build receipt contract (1.6/1.7/1.8):** each selected native build generates `native-build-receipt.json` in its isolated output directory, consumed by `ship.sh`. Common fields are `platform`, `architecture`, `version`, `build`, `artifact_path`, `trust_state`, `checksum_scheme`, `checksum`; schemes are `sha256-bundle-manifest-v1` for the deterministic `.app` bundle-content manifest and `sha256-file` for the Windows installer. Package tests produce/validate it; orchestration tests consume/reject it. It is generated build output, not a new checked-in manifest or dependency.
