## Recorded human decisions

- **A Tag namespace.** The updater reads only GitHub release tags `desktop/vX.Y.Z`, as `desktop.yml` ships them. The `macos/v…`/`windows/v…` split proposed by `desktop-ui-redesign` is **not adopted** for discovery and there is no dual-namespace tolerance. If that change later renames the release tags, this one breaks and must be revised first.
- **B Requirement document.** The human explicitly approves amending `docs/requirements/08-gpui-desktop.md` inside this change (task 1.7).
- **C Dependencies.** `ed25519-dalek` 2.x (no default features) and `sha2` 0.10 are approved for `snackpilot-core`, with no feature flag; they compile for every consumer including the mobile artifacts.
- **D Default and privacy.** The automatic check defaults to on; `docs/privacy.html` gets one factual paragraph about the daily GitHub request, and the clause `Es bestehen keine Verbindungen zu sonstigen Dritten` in the same section is amended to name GitHub Releases as its only exception (task 1.5, human-approved).

## Human prerequisites (not tasks; the coder never does these)

- **P1 Remaining requirement wording.** Outside `08`: a pointer in `docs/requirements/07-release.md` for the manifest assets and the `desktop/v*` namespace, and the `REQ-DST-01`/`REQ-DST-04` "no updater" wording once `desktop-ui-redesign` is archived. Neither is edited by any task here.
- **P2 Signing key — DONE.** The Ed25519 pair was generated with OpenSSL 3.0 and a `pkeyutl -sign/-verify` round trip was run on a sample manifest. The private key is stored as the Forgejo secret `SNACKPILOT_UPDATE_SIGNING_KEY`; the public half is pinned under "Key" in `design.md`. The private key never enters the repository, a prompt or a log, and the throwaway copy was deleted after the round trip. Rotation is not implemented: replacing the secret invalidates the pinned key in every shipped build, so a new key means a new app build with the new public half.
- **P3 CI approval.** The human approves the single new `desktop.yml` step of task 1.6.
- **P4 Sequencing.** Land after `desktop-ui-redesign` tasks 1.6 and 1.7 (this change edits `desktop/mod.rs` and `platform/desktop.rs`, which they also edit).

## Conventions for every task

- One task at a time, in order; no worktree. Two fix rounds counting a red check and review findings together, then stop for the human (`AGENTS.md`).
- `deps:` names **new dependencies/tools**, not earlier tasks. `none` forbids manifest and lockfile edits. File lists are edit allowlists including new files.
- `check:` is `make check`. It runs core tests, model tests and the shell tests wired into `make test-lib`; it does **not** run app-crate tests or native runs. Where a task needs those it names them, and a missing host is `BLOCKED(host)`, never a PASS inferred from compilation.
- Every added or changed test carries `// @req REQ-UPD-…` (shell: `# @req …`) naming a requirement of `specs/desktop-update/spec.md`. Document-only edits (1.7 and the privacy page in 1.5) have no code test; their done bar is the stated `grep`/`git diff` check.
- No task changes a Gourmet or Ventopay request shape. Every task's diff must leave `src/core/tests/wire_audit.rs`, `src/core/src/gourmet/**`, `src/core/src/ventopay/**` and `src/core/src/http/**` untouched; the review checks it with `git diff --name-only`.
- No real credentials, tokens, private keys, cookie jars or live responses in the repository, a test, a log or a prompt. Tests never reach a real host.
- Host Mac means `make mac-sync`, then `ssh mac` with `export PATH=/opt/homebrew/bin:$HOME/.cargo/bin:$PATH` first in every remote command, in `~/vm-sync/SnackPilot-gpui`. Windows means the human-provided Windows 11 x64 host used by `desktop-ui-redesign` 1.7; if absent the Windows-only proof is `BLOCKED(host)`.
